# Оценка качества ИИ

Здесь лежит то, на чём сравниваются модели: девять контекстов одного контрагента с вымышленными данными и указанием, что правильный ответ обязан сказать, а чего говорить не должен.

- `scenarios.py` — сами сценарии. Чистый код: сеть, файлы и часы не трогаются.
- `bench.py` — прогон: задаёт каждой модели одни и те же девять вопросов и печатает таблицу.
- `results/` — подробности прогонов (создаётся сама, в репозиторий не кладётся).

Разбор наших собственных заслонов — отдельный набор, `tests/unit/test_ai_evals.py`: там ответы написаны руками, и проверяется, что `domain/ai_review` судит их правильно. Он выполняется всегда и без сети. Здешний набор отвечает на другой вопрос: **какую модель брать**.

## Как прогнать

Нужны ключ провайдера в `AI_API_KEY` и доступ к нему из сети — то есть машина в России.

```bash
# что вообще в наборе (без ключа и без сети)
PYTHONPATH=src python evals/bench.py --dry-run

# какие модели есть: самые новые, принимающие строгую схему, с ценами в рублях
PYTHONPATH=src python evals/bench.py --catalog --limit 15

# сам замер
PYTHONPATH=src python evals/bench.py --models openai/gpt-4.1-mini,google/gemma-3-27b-it

# модель без поддержки response_format (российское хранение)
PYTHONPATH=src python evals/bench.py --models sber/gigachat-2 --no-schema
```

Таблица печатается в консоль и складывается в `results/` вместе с полным JSON. Её и стоит приносить в PR.

## Что меряется

| Столбец | Что значит |
| --- | --- |
| Принято | Ответ прошёл проверку S5-06: формат, ссылки на основания, никаких новых чисел и дат |
| Без замечаний | Принят **и** прошёл словарные проверки сценария |
| Отклонения | Коды S5-06 с количеством — видно, на чём именно модель спотыкается |
| ₽ за прогон | Сумма `usage.cost_rub` по всем девяти вызовам |
| Секунды | Медиана по вызовам; на длинном сценарии время заметно больше |

Словарные проверки грубые: они ловят модель, которая сказала запретное («признана банкротом» о действующей организации) или не сказала обязательного. Хорошее объяснение от скучного они не отличают — для этого у сценариев есть признак «читать», и такие ответы печатаются целиком, чтобы их прочёл человек. Итоговая оценка полезности — за специалистом на пилоте (S6-05).

## Набор

Девять случаев: долгая просрочка, клиент замолчал, дыры в пакете, противоречие файлов, сообщения ЕФРСБ по чужим делам, спокойный контрагент, обещание оплаты в комментарии, инструкция внутри комментария, сотня взаимодействий. Подробнее — `docs/ai-evals.md`.

Все данные вымышленные. Настоящие выгрузки заказчика в репозиторий не кладутся, и сценарии повторяют только форму.

## Что набор не заменяет

Оценку специалиста на его собственных данных. Модель, прошедшая девять сценариев, годится к пилоту, а не признана полезной.

## Контракт полноты — пункт перед объединением

Добавлен `Coverage.UNAVAILABLE`, совпадающий с `docs/scoring.md`.

| Ситуация | status | coverage | Данные и ограничения |
| --- | --- | --- | --- |
| Проверен весь запрошенный диапазон, записи есть или их нет | `ok` | `complete` | Факты могут быть пустыми; период и источник показываются |
| Проверена только часть диапазона | `ok` | `partial` | Сохраняется проверенная выборка, в `missing` записана причина |
| Раздел не найден или не удалось получить пригодный результат | соответствующий статус ошибки | `unavailable` | Фактов и оснований нет, обязательны `error` и `missing` |

Неполная проверенная выборка может быть пустой: отсутствие записей на одной прочитанной странице не означает, что остальные страницы проверены. Если следующие страницы недоступны, возвращаем пригодную часть как `ok/partial` с причиной ограничения. `FetchStatus` описывает результат раздела, а не код последнего HTTP-запроса. Полнота всего анализа рассчитывается отдельно по базовому набору скоринга.

Тесты покрывают все пять неуспешных статусов в сочетании с тремя значениями полноты; успешный `unavailable`, отказ с фактами и недоступность без причины/ошибки отклоняются.

## Остальные пункты PR #1

1. Добавлены `FactKind` и `CompanyStatus`. Код карточки использует значения из `domain.external`; свободные строки при создании фактов и статуса компании отклоняются. Неизвестный статус — `None` с причиной, пока адаптер не умеет сопоставить его.
2. Синтетический ИНН `0000000000` имеет корректную контрольную сумму; отдельно исключать его валидатором S1-01 не требуется. ИНН в демо не означает существование организации. Сам валидатор остаётся за A.
3. Для `bankruptcy_event` записан TODO S1-05/S3-04: структурированный код события, дата, ID и обработка отмен. Демотекст используется только для карточки, не для правила `confirmed_procedure`.
4. Ветка PR #1 содержит коммиты PR #2 с сохранением авторства и разрешёнными конфликтами документации. PR #2 можно объединить первым: его коммиты уже учтены. Ни один PR автоматически не объединялся.
5. Для раздела компании теперь `covered_period=None`, дата статуса находится в `Fact.observed_on`. Годовой период остался у финансов и выборки событий.

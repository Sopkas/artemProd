## Подключение

В проверенном каталоге плагинов готового подключения YouGile не найдено. Найден сторонний [yougile-mcp](https://github.com/nebelov/yougile-mcp) с `skill/SKILL.md`: инструкции навыка просмотрены, сам сервер не установлен и не проверен в работе. Для переноса задач можно обращаться напрямую к официальному REST API v2; установка MCP не обязательна.

По [официальной инструкции](https://help.yougile.com/books/baza-znanii-yougile/page/rest-api-v20-v-yougile) API бесплатен, ключ наследует права пользователя. Приложение на компьютере не предоставляет автоматический доступ агенту.

1. Открыть свою компанию в YouGile. Скопировать ID компании: `Ctrl+Option+Q` на Mac или `Ctrl+Alt+Q` на Windows. Часть ссылки команды не подставлять вместо ID компании.
2. Открыть [создание API-ключа](https://ru.yougile.com/api-v2#/operations/AuthKeyController_create). В интерактивной консоли указать собственные `login`, `password` и `companyId`, отправить запрос. Пароль вводить только на официальном сайте.
3. Значение `key` сохранить в локальном, исключённом из Git `.env` как `YOUGILE_API_KEY=...`. Существующие настройки Telegram сохранить. Это настройка инструмента работы с задачами, оболочка бота её не использует.
4. После получения доступа прочитать проекты, доски, участников и существующие задачи. Сопоставить участников с ролями: B — Sopkas, A — коллега. Уточнить соответствие, если имена аккаунтов неоднозначны.

## Доска и карточки

Использована существующая пустая доска проекта Artemka; она переименована в «Разработка». Роль A назначена второму участнику проекта — Сергею, B — Sopkasss. Создан стикер «ArtemProd · Спринт». Оценки заданы в часах; фактическое время не учтено.

[Соответствие ID roadmap и YouGile](yougile-tasks.json) сохранено для последующих обновлений без дубликатов. Подключение выполнено напрямую по API; сторонний MCP не установлен.

Колонки: **Бэклог → К выполнению → В работе → На проверке → Готово**. Для задач, ожидающих внешнего условия, отдельная колонка **Ожидание** с указанием причины.

Каждая задача из roadmap получает:

- ID в заголовке: например, `S1-04 — Общие типы и демопровайдер`;
- одного исполнителя из участников YouGile и обозначение роли A/B;
- спринт и оценку в часах;
- исходное описание, критерии приёмки и зависимости;
- ссылку на документацию или результат, а для выполненного кода — коммит/CI;
- причину ожидания, если задача заблокирована.

Сроки не назначать до подтверждения даты защиты и загрузки команды. Все задачи будущих спринтов исходно находятся в бэклоге; «В работе» означает фактически начатую задачу.

- Перед созданием проверить все страницы списка существующих задач, включая завершённые; сверять ID `S0-01` и т. п. Повторный перенос не должен создавать дубликаты.
- Сохранить соответствие ID roadmap и ID/ссылок YouGile после создания. Проверить чтением исполнителей, описания и статусы.
- Не менять существующие чужие задачи и настройки компании ради импорта. Не отправлять сообщения в чаты задач.
- В YouGile вести ежедневные статусы и назначения, в roadmap — объём и критерии приёмки. Изменение объёма отражать в обоих местах; журнал хранит только важные итоги.

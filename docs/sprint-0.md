### Замечания A к договорённостям (16.09.2026)

Ответ B и реализация согласуемых уточнений: [разбор ревью S1-04](review-s1-04.md). Исходные замечания ниже сохранены для контекста; повторное согласование ещё ожидается.

1. **Windows.** Проект требует Python ≥ 3.12; README и CI проверены только на macOS/Linux. Рабочая машина A — Windows 11. Предложение: добавить в CI job на `windows-latest` и Windows-команды установки в README (`.venv\Scripts\activate`), либо явно договориться, что A работает в WSL.
2. **Состояние диалога для S1-02.** Архитектура говорит, что оболочка не использует состояние диалогов, а ввод ИНН с отменой требует FSM aiogram. Предложение: в спринте 1 — `MemoryStorage` (диалог короткий, потеря при перезапуске допустима); в БД спринта 2 хранится только `AnalysisRun`, состояние FSM в SQLite не переносится.
3. **Валидатор ИНН (S1-01).** Один общий валидатор в `domain`, владелец A, ревьюер B; вызывается из прикладного сценария, а не из обработчика Telegram, чтобы импорт Excel использовал ту же функцию. Демосценарии S1-04 должны использовать синтетические ИНН, проходящие валидатор, иначе сценарий S1-03 не соберётся целиком.
4. **`Fact.kind` в S1-04 — строка.** Для карточки S1-03 нужен фиксированный минимальный набор типов фактов (`company_name`, `company_status`, `revenue`, `net_profit`, `bankruptcy_event`) как константы или `StrEnum` в `domain`, а не «магические строки». Замечание передаётся в ревью PR #1.
5. **Где ежедневная сверка.** Roadmap §4 п. 7 требует ежедневную сверку, а правила YouGile запрещают писать в чаты задач. Предложение: статусы — в описании карточки, обсуждение — в комментариях PR; либо разрешить чат задач.
6. **Имена веток.** Roadmap предлагает `feat/S1-02-…`, фактически используется `codex/s1-04-…`. A использует `feat/<ID>-<slug>`; договориться о единой схеме или разрешить префикс по инструменту.

# Инструкция пользователя

Для специалиста, который работает с должниками. Разработчик для этого не нужен: всё делается в Telegram, по шагам ниже.

## Что делает бот

Бот отвечает на три вопроса: с кем работать в первую очередь, какие факты это объясняют и что проверить дальше. Для этого он объединяет ваши файлы (долги, платежи, взаимодействия, договоры) со сведениями из открытых источников: статус организации, сообщения о банкротстве (ЕФРСБ), выручка и прибыль.

**Приоритет считают правила, а не ИИ.** У каждой причины есть значение, дата и источник. Если данных не хватает, бот пишет «недостаточно данных», а не «рисков нет». Отчёт помогает расставить очерёдность, но не является юридическим заключением и не оценивает вероятность банкротства.

## Перед началом

1. Найдите бота в Telegram по имени, которое дал разработчик, и нажмите «Запустить» (`/start`).
2. Если бот ответил «Доступ к боту ограничен» и показал ваш Telegram ID, перешлите это сообщение разработчику. Он добавит вас в список, после этого снова нажмите `/start`.
3. Бот работает только в личной переписке, в группах он молчит.

## Одна организация: «Проверить ИНН»

1. Нажмите «Проверить ИНН» (или `/inn`).
2. Отправьте ИНН: 10 цифр для организации или 12 для ИП. Если в ИНН опечатка, бот объяснит, что не так, и попросит ввести снова.
3. Бот пришлёт карточку. В ней:
   - **Организация:** название и статус;
   - **Сообщения о банкротстве:** каждое с датой и ссылкой на федресурс;
   - **Финансы:** выручка и чистая прибыль за последние годы;
   - у каждого раздела — источник, дата получения и полнота («проверено полностью», «неполные данные», «раздел недоступен» с причиной);
   - **Внутренние данные**, если эта организация была в одной из ваших проверок: долг, просрочка, давность платежа, договоры, последние взаимодействия;
   - строка о том, что бот **не проверяет сам**, со ссылкой, где проверить вручную (сейчас это блокировки счетов ФНС).

Приоритета в карточке нет: он считается только в проверке списка, где есть ваши данные о долге.

## Проверка списка: «Новая проверка»

### 1. Дата анализа

Нажмите «Новая проверка» (или `/check`). Бот спросит дату анализа — день, на который считаются долги и просрочка. Нажмите «Сегодня» или введите дату как ДД.ММ.ГГГГ.

### 2. Файл «Контрагенты» (обязательный)

Бот пришлёт шаблон. Заполните лист «Контрагенты»: одна строка на организацию, ИНН обязателен, долг и просрочку укажите, если они есть. Отправьте файл `.xlsx` до 10 МБ.

Бот покажет сводку: сколько организаций принято и какие строки с ошибками (с номером строки и причиной). Строки с ошибками в проверку не попадут. Если ошибок много, исправьте файл и начните проверку заново.

### 3. Дополнительные файлы (по желанию)

На шаге подтверждения можно добавить файлы. Каждый делает отчёт полнее; без них соответствующие показатели будут «недостаточно данных».

| Кнопка | Что прислать | Зачем |
| --- | --- | --- |
| «Добавить платежи» → «По нашему шаблону» | Лист «Платежи» по шаблону бота. Сначала бот спросит период, за который выгрузка **полная**: указывая его, вы подтверждаете, что в файле есть все поступления за этот период | Давность последнего платежа |
| «Добавить платежи» → «Выгрузка из 1С» | Печатную форму 1С по **одной** организации, как есть (`.xlsx` или `.xls`). Бот спросит ИНН этой организации (в самом файле его нет) и возьмёт период из шапки | То же, без перепечатывания |
| «Добавить историю долга» | Лист «История долга» по шаблону | Как менялся долг за месяц |
| «Добавить взаимодействия» | Лист «Взаимодействия» по шаблону: дата, комментарий, канал | Хронология в отчёте; обещания оплаты в пояснении |
| «Добавить отчёт по договорам» | «Отчёт по просроченным лизинговым платежам» из 1С как есть (`.xlsx` или `.xls`) | Договоры с их собственной просрочкой и суммой |

После каждого файла бот показывает состав пакета. Тот же файл второй раз не добавится. «Отмена» внутри добавления файла возвращает к пакету, ничего не теряя.

Договоры из отчёта привязываются к организациям **по названию**: в отчёте нет ИНН. Названия, которые не совпали или совпали у двух организаций сразу, будут перечислены на листе «Качество данных», договоры по ним не приписываются никому.

### 4. Запуск

Нажмите «Запустить проверку». Перед запуском бот проверит пакет целиком и покажет сквозные замечания, например, если один и тот же платёж есть в двух файлах с разными суммами. Если замечание блокирует запуск, бот скажет, что исправить.

Проверка идёт в фоне, бот при этом отвечает на другие команды. Ориентир — около 5 минут на 50 организаций. Состояние — «Статус» (`/status`).

### 5. Результат

Когда проверка закончится, бот пришлёт сводку (сколько организаций, сколько проверено полностью, сколько в каждом приоритете) и файл отчёта. Получить отчёт ещё раз — «Отчёт» (`/report`).

## Как читать отчёт

| Лист | Что на нём |
| --- | --- |
| **Приоритеты** | По строке на организацию: долг, просрочка, приоритет, полнота, причины, следующий шаг, пояснение, обещания оплаты, число договоров и худшая просрочка по договору |
| **Основания** | Каждый факт, на который опирается причина: значение, дата, источник, ссылка |
| **Качество данных** | Ошибки и предупреждения по вашим файлам (файл, лист, строка) и по источникам |
| **О проверке** | Дата анализа, режим (реальные данные или демо), версия правил, свежесть внешних данных, состав пакета, что не проверяется автоматически |
| **Хронология** | Взаимодействия по организациям, если был файл «Взаимодействия» |
| **Договоры** | Договоры из отчёта по договорам, если он был |

**Приоритеты:**

| Приоритет | Что значит |
| --- | --- |
| Критичный | Подтверждённый серьёзный сигнал: организация ликвидируется. В этой версии из статусов источника распознаётся только «Действует», поэтому на реальных данных «Критичный» пока не появляется; другой статус виден в карточке и в «Основаниях» |
| Высокий | Существенное ухудшение (просрочка больше 60 дней, сообщение о банкротстве) или сочетание сигналов |
| Средний | Отдельные основания для внимания (просрочка 31–60 дней, нет платежей больше 60 дней, долг вырос вдвое за месяц, выручка упала на 30%, убыток). Два разных таких основания дают «Высокий» |
| Низкий | В полном наборе проверок значимых сигналов нет |
| Недостаточно данных | Сигналов нет, но и проверка неполная. Это не «всё хорошо» |

Полная проверка и приоритет — разные вещи: серьёзный сигнал оставляет высокий приоритет, даже если другой источник недоступен.

**Пояснение** начинается с «ИИ:», если его написала модель, или с «По правилам:», если модель выключена, не ответила или её ответ не прошёл проверку. Модель не меняет приоритет, она только объясняет его словами.

**Проверка завершена частично** (`partial`) — это нормально: отчёт построен, а на «О проверке» и в сводке сказано, чего не хватило (строки с ошибками, недоступный раздел источника, исчерпанный лимит).

## Демо и реальные данные

Если в карточке или отчёте стоит «ДЕМО», сведения синтетические и к реальным организациям не относятся. Режим задаёт разработчик при запуске бота, сами вы его не переключаете.

## Если что-то пошло не так

| Что видите | Что делать |
| --- | --- |
| «Нужен файл .xlsx» | Сохраните файл в Excel как `.xlsx`. Выгрузки 1С принимаются и в `.xls` |
| «Файл больше 10 МБ» | Разбейте список на две проверки |
| «Файл не принят» со списком строк | Исправьте названные строки и отправьте файл снова |
| «Проверка не запущена» | Исправьте замечание из сообщения и снова нажмите «Запустить проверку» |
| Много «недостаточно данных» | Добавьте платежи и историю долга; посмотрите «Качество данных» |
| Раздел источника «недоступен» | Источник не ответил или исчерпан его лимит. Повторите проверку позже |
| «Не удалось отправить файл» | Нажмите «Отчёт» ещё раз |
| Бот не отвечает | Отправьте `/start`. Если не помогло, напишите разработчику |

Известные ограничения текущей версии — в [заметках к выпуску](release-notes.md).

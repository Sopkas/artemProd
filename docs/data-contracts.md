# Контракты данных

Статус: предлагаемый шаблон MVP. Реальные выгрузки заказчика ещё не получены; поддержка произвольных отчётов 1С не предполагается.

18.09.2026 (S2-04) реализованы шаблон и парсер обязательного листа «Контрагенты» ниже: `domain/counterparties.py` (правила контракта), `application/imports.py` (интерфейс читателя и оркестратор), `infrastructure/excel/` (чтение через openpyxl и генератор шаблона). Ошибки и предупреждения возвращаются единым списком `domain.imports.ImportIssue` (S2-03) со стабильными `code` и `severity`. Листы «Платежи» и «История долга» разбираются с S4-05 (`domain/payments.py`, `domain/debt_history.py`, `application/ledger_imports.py`) и с S4-01 добавляются в пакет из Telegram как отдельные необязательные файлы (`application/check_package.accept_ledger`; период платежей — `UploadedFile.coverage`). «Взаимодействия» — S4-02.

## Общие правила

- Формат `.xlsx`, первая строка — заголовки. Пользователь указывает тип файла при загрузке; ожидается лист с именем из таблиц ниже.
- Заголовки фиксированные, по-русски. Пробелы по краям удаляются. Неизвестные колонки игнорируются с уведомлением; дубли обязательных колонок являются ошибкой.
- ИНН хранится как текст из 10 цифр и проверяется по контрольной цифре. Числовая ячейка принимается только при точном восстановлении целого значения из 10 цифр. Потерянные цифры не угадываются. ИНН из 12 цифр в первой версии получает отметку «тип контрагента не поддерживается».
- Дата — дата Excel либо строка `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`. Неоднозначные даты отклоняются.
- Суммы — рубли с точностью до копеек; допускаются числовые ячейки и строки с десятичной запятой. Разделители разрядов — обычный, неразрывный, узкий неразрывный и тонкий пробелы. Валютные долги в MVP не смешиваются.
- Пустое значение означает «неизвестно», ноль — известное нулевое значение. Формулы во входных колонках не вычисляются и требуют замены на значения.
- Пакет имеет единую дату анализа. Финансовые периоды и события после этой даты исключаются с пояснением. Внешние сведения отражают момент запроса, поэтому MVP не обещает восстановить внешнее состояние компании на историческую дату.
- Ошибки возвращаются с файлом, листом, строкой, колонкой и причиной. Если пригодных строк нет, внешняя проверка не запускается. Общая форма — `domain.imports.ImportIssue`: стабильный `code` (snake_case), `severity` (`error` — строка или файл непригодны, `warning` — принято с замечанием), `sheet`, `reason` без содержимого ячеек, `row` — номер строки Excel с 1 или `None` для листа/файла, `column` — буквы колонки или `None` для ошибки строки, `file_id` проставляет сценарий загрузки. Парсеры возвращают один список, а не отдельные ошибки и предупреждения.

## 1. Контрагенты — обязательный файл

Лист `Контрагенты`, одна строка на ИНН. Минимальный режим — только ИНН; остальные поля расширяют анализ.

| Колонка | Обязательность | Значение |
| --- | --- | --- |
| `ИНН` | Да | Ключ сопоставления |
| `Наименование` | Нет | Название из учётной системы; название поставщика хранится отдельно |
| `Дата среза` | При наличии долга или просрочки | Должна совпадать с датой анализа |
| `Сумма долга` | Нет | Неотрицательный остаток на дату среза |
| `Дней просрочки` | Нет | Целое неотрицательное число, максимальная просрочка по неоплаченным обязательствам |
| `Дата последнего платежа` | Нет | Известная дата последнего поступления на дату анализа |

Полностью одинаковые строки объединяются с предупреждением. Конфликтующие строки по одному ИНН требуют исправления и не суммируются автоматически. Долги по отдельным договорам заказчик агрегирует в согласованный шаблон.

Отсутствие суммы или просрочки не мешает внешней проверке, но исключает соответствующий внутренний показатель. Загрузка с одним ИНН не получает полный внутренний скоринг.

## 2. Платежи — дополнительный файл

Лист `Платежи`, одна строка на поступление. При загрузке пользователь указывает начало и конец покрываемого периода и подтверждает, что выгрузка полная за этот период.

| Колонка | Обязательность | Значение |
| --- | --- | --- |
| `ИНН` | Да | Контрагент из обязательного файла |
| `ID платежа` | Да | Уникальный ID операции для данного ИНН |
| `Дата платежа` | Да | Дата поступления |
| `Сумма платежа` | Да | Положительная сумма; возвраты и сторно требуют отдельного будущего формата |

Повтор одного ID с теми же данными пропускается с предупреждением; с другими данными — ошибка. Два разных ID с одинаковой датой и суммой остаются разными платежами. Строки с ИНН вне пакета не добавляют новых контрагентов и попадают в ошибки.

Максимальная дата поступления становится подтверждённой датой последнего платежа только при полном покрытии до даты анализа и согласованности с основным файлом. Иначе выводится «последний платёж в предоставленном периоде». При противоречии источников показатель давности считается неизвестным до исправления, конфликт показывается пользователю.

Одни поступления не позволяют вычислить просрочку: нужны сроки оплаты и привязка к обязательствам. В MVP дни просрочки берутся из основного файла. Из пустой неполной истории нельзя заключить, что клиент перестал платить.

Реализация (S4-05): `domain/payments.py` (`parse_payments`), чтение из книги — `application/ledger_imports.import_payments`. Коды: `payment_id_missing`/`_invalid`, `payment_date_missing`, `payment_amount_missing`/`_zero`/`_negative`/`_not_number`/`_precision`, `inn_not_in_package` (строка отброшена), `payment_after_analysis_date` (предупреждение, строка исключена), `duplicate_payment` (предупреждение), `payment_id_conflict` (ошибка; принятой остаётся первая строка). ID платежа уникален в пределах ИНН; числовой ID принимается только целым. Покрываемый период и «последний платёж» вычисляются по подтверждённому при загрузке периоду в S4-06, а не при разборе листа: `domain/indicators.payment_recency` (правила и статусы — `docs/scoring.md`, «Внутренние показатели»). Периоды нескольких выгрузок склеиваются, только если идут без разрыва.

## 3. Взаимодействия — дополнительный файл

Лист `Взаимодействия`.

| Колонка | Обязательность | Значение |
| --- | --- | --- |
| `ИНН` | Да | Контрагент из пакета |
| `ID взаимодействия` | Да | Уникальный ID записи для ИНН |
| `Дата взаимодействия` | Да | Дата события |
| `Комментарий` | Да | Текст сотрудника или содержание ответа клиента |
| `Канал` | Нет | Телефон, письмо, встреча и т. п. |

Правила повторов ID и неизвестных ИНН такие же, как для платежей.

Реализация (S4-02): `domain/interactions.py` (`parse_interactions`, `chronology`), чтение — `application/ledger_imports.import_interactions`, в пакет — кнопка «Добавить взаимодействия» (S4-01/`accept_ledger`). Коды: `interaction_id_missing`/`_invalid`, `interaction_date_missing`, `date_invalid`, `comment_missing`/`_invalid`/`_too_long` (до 2000 символов), `channel_too_long` (до 50), `inn_not_in_package` (строка отброшена), `interaction_after_analysis_date` (предупреждение, исключена), `duplicate_interaction` (предупреждение), `interaction_id_conflict` (ошибка; принятой остаётся первая строка). Колонка «Канал» необязательна. Результат — хронология: строки по ИНН в порядке дат. Комментарии — данные владельца: они видны ему в карточке ИНН (S4-04; в карточке обрезаются до 200 символов, блок умещается в одно сообщение Telegram) и на листе «Хронология» его отчёта, но не попадают в замечания импорта, сводки и журналы. ИИ может выделить обещание оплаты с датой и ссылкой на запись. Он не объявляет обещание нарушенным без проверки периода платежей и достаточной связи между обещанием и обязательством. Комментарии не меняют числовой скоринг первой версии.

## 4. История долга — дополнительный файл

Лист `История долга`: `ИНН`, `Дата среза`, `Сумма долга` — все обязательны. Одна строка на ИНН и дату; одинаковые дубли объединяются, конфликтующие являются ошибкой. ИНН должен присутствовать в основном файле, сумма неотрицательна. Исторические срезы должны быть сопоставимы по составу долга.

Для месячной динамики сравниваются текущий срез и срез на дату за один календарный месяц до него; если такого дня в месяце нет, используется последний день месяца. Произвольная ближайшая дата не подставляется. Текущий срез берётся из основного файла; при конфликте с историей показатель неизвестен.

Без предыдущего среза рост долга не рассчитывается. При предыдущем значении ноль процентный рост и отношение не определены; выводится «долг появился» без деления на ноль.

Реализация (S4-05): `domain/debt_history.py` (`parse_debt_history`), чтение — `application/ledger_imports.import_debt_history`. Коды: `cutoff_missing`, `debt_missing`, `debt_*` как в основном файле, `inn_not_in_package`, `cutoff_after_analysis_date` (предупреждение, срез исключён), `duplicate_row` (предупреждение, объединено), `snapshot_conflict` (ошибка). Ноль — известное значение. Сравнение с текущим срезом основного файла и месячная динамика — `domain/indicators.debt_dynamics` (S4-06): база — срез ровно на месяц раньше даты среза строки, при расхождении среза на дату среза с «Контрагентами» динамика неизвестна.

Проверки пакета целиком (S4-03) — `application/package_checks.review_package`: принадлежность файлов проверке (путь файла в каталоге проверки, иначе `PackageIntegrityError` и проверка не выполняется), один файл «Контрагенты» (`counterparties_duplicated`, блокирует запуск), повторы между файлами одного вида — `duplicate_*_across_files` (предупреждение) / `*_conflict_across_files` (ошибка, первый файл остаётся), конфликты дат с основным файлом — `debt_history_conflict` (срез «Истории долга» на дату среза строки «Контрагентов» ≠ её долгу) и `last_payment_conflict` (последний платёж не найден в выгрузке за подтверждённый период или в ней есть более поздний) — по одному предупреждению листа «Пакет» на вид с числом организаций, без ИНН и сумм; какие именно организации — `PackageReview.conflicts` (ИНН → {`debt_history`, `last_payment`}), по нему S4-06 считает показатель неизвестным только у них. Замечания всех файлов несут `file_id`; на листе «Качество данных» он превращается в подпись файла (`domain/report.file_labels`, см. «Выходной Excel»).

Реальная выгрузка заказчика для «Платежей» и «Истории долга» ещё не получена: сопоставление её колонок с шаблоном — после получения файла.

## Выходной Excel

| Лист | Содержимое |
| --- | --- |
| `Приоритеты` | ИНН, название, долг, дни просрочки, приоритет, полнота, причины, следующий шаг |
| `Основания` | ID факта, ИНН, показатель/событие, значение, период, источник, URL или файл/лист/строка |
| `Качество данных` | Ошибки строк, отсутствующие разделы, недоступные источники, конфликты, ограничения выборки |
| `О проверке` | ID, дата анализа, «внешние данные не старее» (время самого старого ответа источника, включая кэш), demo/live, версии правил и ИИ, состав пакета: каждый файл с той же подписью, что на «Качество данных», и для чего использован (давность платежа / динамика долга / хронология) |
| `Хронология` | (S4-04) записи «Взаимодействий» по организациям отчёта в порядке отчёта, затем по дате: ИНН, название, дата, ID, канал, комментарий; без ИИ-прочтения. Если файл не загружен — одна строка об этом |

Реализация (S2-05): вход генератора — доменная модель `domain/report.py` (`AnalysisReport` = `ReportMeta` + строки `ReportRow` + замечания импорта `ImportIssue`). Строка объединяет строку «Контрагенты», её `Assessment` из скоринга (S3-05) и внешние снимки, на которых оценка построена. Генератор `infrastructure/excel/report.py` (`build_report`) только раскладывает модель по листам, ничего не вычисляет и не вызывает.

- Раскладка всех листов одинаковая: строка 1 — заголовок с ID проверки и датой анализа, в демо — пометка «ДЕМО: синтетические данные»; строка 2 — шапка; данные с строки 3, шапка закреплена, есть фильтр.
- Любой текст записывается как текст: значение вида `=HYPERLINK(...)` из файла пользователя или внешнего API не становится формулой. ИНН — текстовые ячейки; долг — число.
- «Приоритеты» — в порядке `report_order_key`; причины содержат ID фактов-оснований. «Основания» — факты внешних разделов с источником и ссылкой на запись и внутренние значения со ссылкой на файл «Контрагенты». «Качество данных» — ошибки и предупреждения импорта (без ИНН) и `missing_data` по каждому ИНН; у замечания файла пакета место начинается с подписи файла — вид, период выгрузки платежей и номер, если файлов этого вида несколько («файл «Платежи за 01.06.2026–30.06.2026, файл 2», лист «Платежи», строка 3»); замечания пакета целиком — первыми, дальше по файлам в порядке загрузки. Время загрузки в подпись не входит (нужен часовой пояс пользователя).
- Демоотчёт контрольного пакета S2-06 (`control_package.demo_report`) несёт заранее заданные демо-оценки: `ReportMeta.demo_scores` допустим только в демо-режиме, отмечен в заголовке каждого листа, в «О проверке» и в причинах строки.

Пользовательские тексты экспортируются как текстовые ячейки, даже если начинаются с `=`, `+`, `-` или `@`. Цвет сопровождается текстовым названием приоритета. Ссылки на основания сохраняются и при отключённом ИИ.

# Список на мониторинге (S8-08, часть B)

Правила, по которым ИНН попадают в список ежедневного мониторинга и уходят из него. Код:
- `domain/watchlist.py` — разбор сообщения и правила списка;
- `application/watchlist_files.py` — ИНН из файла;
- `presentation/telegram/watchlist.py` — сводка для пользователя.

Хранение списка, кнопки и ежедневный запуск — часть A (S8-09). Что считается изменением — S8-06, PR #93.

## О чём договорились с заказчиком (16.10.2026)

- **Список задаёт сам заказчик:** любые ИНН сообщением, файлом или новым отчётом из 1С, а не только организации из отчёта.
- **До 100 организаций** (`WATCH_LIMIT`). Это около 500 запросов Checko в сутки: 5 разделов на организацию. Под этот объём берём тариф.
- **Присланное добавляется к списку.** Ненужные организации можно убрать.

## Как читается сообщение (`parse_inns`)

- **ИНН — любая последовательность из 10 или 12 цифр.** Слова, нумерация («1.», «2)»), суммы, ОГРН и даты вокруг неё не мешают, поэтому годится список, скопированный откуда угодно.
- **Девять или одиннадцать цифр — ошибка, а не пропуск:** скорее всего, потеряна или лишняя одна цифра. Если промолчать, организация останется без мониторинга.
- **Ошибка называется по номеру в сообщении** («№ 2: контрольная цифра не совпадает»). Само значение не повторяется — как везде с ИНН.
- **Повторы** считаются один раз, и бот говорит, сколько их пропущено.

## Как читается файл (`read_watch_file`)

| Файл | Что берётся |
| --- | --- |
| Отчёт из 1С «Отчет по просроченным лизинговым платежам» с колонкой «ИНН» («образец» заказчика) | ИНН и название контрагентов с просрочкой **больше 60 дней** — разбором S7-01 (S8-14, см. ниже). На «образце» 318 организаций, ИНН есть у всех |
| Тот же отчёт без колонки ИНН | Ничего: по названию мониторинг не ведётся. Бот так и пишет и просит вариант с ИНН или ИНН сообщением. Это сообщение — раньше отбора по дням |
| Таблица с колонкой «ИНН» (шапка в одной из первых 20 строк) | ИНН из этой колонки; название — из колонки «Наименование», «Название», «Контрагент» или «Организация», если такая есть. Ошибки — по номеру строки листа |
| Таблица без шапки («тпз 3», столбик ИНН) | ИНН из колонки, где больше всего действительных ИНН. Контрольная сумма не даёт принять за ИНН дату или сумму. В этой колонке читается только то, что похоже на ИНН: даты договоров в строках под организацией пропускаются |

### Отбор отчёта 1С по просрочке (S8-14)

Заказчик, 17.10.2026, ответ на вопрос 8: «Всех с просрочкой больше 60 дней». В «образце» 318 организаций, а в списке до 100 — без отбора в список шли первые сто по порядку отчёта.

- **Порог — `WATCH_OVERDUE_DAYS` (60), настройка `MONITORING_OVERDUE_DAYS`** (целое, не меньше 0). Граница строгая, как у `OVERDUE_HIGH_AFTER_DAYS` в скоринге: 60 дней — не берётся, 61 — берётся.
- **Организация оценивается один раз**: сначала её записи под разными точками продаж склеиваются (`merge_repeats`), потом берётся худший договор (`CounterpartyDebt.worst_days`). 30 дней по одному договору и 90 по другому — должник на 90 дней. Организация — это её ИНН (`watchlist_files._merged`): записи с одним ИНН склеиваются, даже если название напечатано по-разному (дубль в справочнике 1С), имя — из первой записи; две организации с одинаковым названием и разными ИНН — две, и каждая оценивается по своим дням. Запись без ИНН присоединяется к ИНН своего названия, если в отчёте это название носит ровно один ИНН (ячейка ИНН пуста только под одной точкой продаж); если два и больше — чья она, неизвестно, и запись остаётся отдельной. Записи без ИНН между собой склеиваются по названию, как раньше.
- **Без дней просрочки** (ни у одного договора нет «Дней») — оценить нельзя: не добавляется, но считается и называется в ответе.
- **Ответ бота** — сразу под «Добавлено»: сколько организаций в отчёте, у скольких просрочка больше порога, сколько не взято с меньшей просрочкой и сколько без дней. ИНН и лимит проверяются уже среди отобранных: «Без ИНН среди отобранных» (у отчёта без отбора — «Без ИНН в отчёте»), «Не добавлены — на мониторинге не больше 100» — как раньше.
- **Если не прошёл никто** — вместо «Добавлено: 0» бот пишет, что ни у одной из N организаций отчёта нет просрочки больше 60 дн. (у отчёта из одной организации — «У единственной организации отчёта…»), и предлагает прислать нужные ИНН сообщением.
- **Таблица с колонкой «ИНН», столбик ИНН без шапки и ИНН сообщением не отбираются** — это список, который пользователь составил сам.

**ИНН с потерянным ведущим нулём** (Excel хранит его числом) не дополняется нулём: девять цифр — это ошибка в строке. Правило то же, что во всём проекте: цифры не угадываются.

## Правила списка (`add`, `remove`)

- **Новое добавляется в порядке присланного, пока список не заполнен.**
- **Что уже было в списке, называется отдельно** («уже были на мониторинге: 12»).
- **Сверх лимита ничего не добавляется, и из списка ничего не вытесняется.** Решать, кто больше не нужен, — заказчику. Бот называет, что не вошло (первые пять и «…и ещё N»), и просит убрать ненужные.
- **Удаление — по ИНН, пачкой.** ИНН, которого в списке не было, называется, но это не ошибка.

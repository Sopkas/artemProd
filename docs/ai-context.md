# Контекст и инструкция для ИИ — v1 (проект, S5-05)

Что именно уходит модели по одному контрагенту и по каким правилам. Документ согласуется с A до S5-01: провайдер (S5-01) отправляет ровно то, что описано здесь, хранение версий — S5-02, лимиты и бюджет — S5-03, проверка ответа — S5-06.

**До согласования состава данных с заказчиком реальных запросов нет.** Контекст собирается и проверяется тестами, но наружу не отправляется: выбор провайдера, допустимые данные и лимит расходов — открытый пункт S5-01.

## Роль ИИ

Приоритет, сигналы и базовую рекомендацию считают правила (`docs/scoring.md`). Модель их **не меняет**: она объясняет специалисту готовый результат своими словами и отдельно перечисляет обещания оплаты из комментариев. Если модель недоступна или её ответ отклонён, отчёт выходит с базовой рекомендацией (S5-04).

## Что уходит модели

`domain/ai_context.build_context(...) → RecommendationContext`, `build_request(context) → Request` (инструкция + `context.as_dict()`, готовый к JSON).

| Часть | Содержимое | Откуда |
| --- | --- | --- |
| `inn`, `analysis_date` | ИНН этого контрагента и дата анализа | «Контрагенты» |
| `priority`, `signals[]`, `next_step`, `base_complete`, `rules_version` | Результат правил как есть: код сигнала, уровень, причина, значение, дата, ID оснований | `Assessment` (S3-05) |
| `values[]` | Внутренние значения и показатели с ID основания: долг, просрочка, давность платежа, динамика долга и выручки | «Контрагенты» + показатели (S4-06) |
| `facts[]` | Внешние факты: раздел, название, значение, источник, ID записи, дата или период, единица | Снимки Checko (S3-04) |
| `comments[]` | Взаимодействия: ID, дата, канал, текст комментария | «Взаимодействия» (S4-02) |
| `missing_data[]` | Чего не хватает и почему | `Assessment` |
| `comments_omitted` | Сколько старых комментариев не поместилось в лимит | — |
| `context_version`, `instruction_version` | Версии этого контракта и инструкции | константы модуля |

Неизвестное значение факта в `facts[]` не попадает: пробел живёт в `missing_data`, чтобы модель не приняла «нет данных» за значение.

## Чего в контексте нет

- Данных другого контрагента. Чужой `Assessment`, показатели или снимок — ошибка (`ValueError`), строки «Взаимодействий» чужих ИНН отбрасываются: файл общий на пакет.
- Сведений о пакете, пользователе, проверке и файлах: ни `run_id`, ни Telegram ID владельца, ни путей и имён файлов.
- Чего-либо от предыдущих проверок или других организаций: запрос собирается заново по одному контрагенту.

## Факты отдельно от комментариев

`values[]` и `facts[]` — проверенные данные с источником. `comments[]` — слова сотрудника или клиента; инструкция требует писать о них как о словах («клиент сообщил»), а не как о фактах. Комментарий не участвует в расчёте приоритета (`docs/scoring.md`) и не попадает ни в значения, ни в факты.

**Обещания оплаты.** Каждый комментарий несёт `interaction_id` и дату, поэтому обещание в ответе модели ссылается на конкретную запись. Модель отмечает обещание, только если в комментарии есть и обещание, и дата, и не объявляет его нарушенным: это проверяется по платежам (S4-06). Проверку ссылок в ответе делает S5-06.

## Лимиты контекста

`ContextLimits`: `include_comments` — отправлять ли комментарии вообще (см. открытые пункты); не больше 20 последних комментариев (остальные считаются в `comments_omitted`), не больше 500 символов на комментарий — длинный обрезается с пометкой `truncated`. Комментарии идут по возрастанию даты. Общий лимит запроса, времени и повторов — S5-03.

## Инструкция

Текст — `domain/ai_context.INSTRUCTION`, версия — `INSTRUCTION_VERSION`. Коротко, что в ней запрещено: менять приоритет, добавлять суммы, даты и события, которых нет во входных данных, ссылаться на что-то кроме переданных ID, называть обещание нарушенным, давать юридические указания и процессуальные сроки, заполнять пробелы догадками.

Любое изменение текста инструкции или состава контекста — новая версия (`INSTRUCTION_VERSION` / `CONTEXT_VERSION`). `versions()` даёт строку для «О проверке» и для сохранённого объяснения (S5-02), чтобы было видно, чем получен ответ.

## Ответ модели и его проверка (S5-06)

Ответ — один объект JSON: `explanation` (2–4 предложения, до 1200 символов), `promises[]` (`interaction_id`, `due_on`, необязательная `quote`) и `grounds[]` (ID оснований и взаимодействий). Версия схемы — `ai_review.ANSWER_SCHEMA_VERSION`.

`domain/ai_review.review_answer(payload, context)` возвращает либо `Explanation`, которую можно показывать, либо `Rejected` с кодом; исключений не бросает. Коды отклонения:

| Код | Когда |
| --- | --- |
| `not_json` | Ответ не разобран как JSON |
| `schema` | Не объект, лишние или отсутствующие поля, не тот тип, слишком много обещаний |
| `empty_explanation` / `too_long` | Пустое объяснение; длиннее 1200 символов |
| `unknown_ground` | Ссылка на основание, которого нет в контексте |
| `unknown_interaction` | Ссылка на взаимодействие, которого нет в контексте (в том числе когда комментарии не отправлялись) |
| `new_amount` / `new_date` | Число или дата, которых нет во входных данных |
| `priority_changed` | Назван другой уровень приоритета или предложено его изменить |
| `promise_without_date` | Обещание без даты или с нечитаемой датой |
| `promise_not_in_comment` | Даты обещания (или цитаты) нет в комментарии, на который оно ссылается |

Отклонённый ответ — не ошибка проверки: специалист видит базовую рекомендацию правил (S5-04), а код отклонения можно считать и показывать. Пересказ округлённого числа допускается: `-40.0%` из контекста может стать «40 %», а `5000` при долге `1000.00` — нет.

**Известное ограничение:** проверка чисел строгая, поэтому оборот вроде «в ближайшие 2–3 недели» тоже будет отклонён как новое число. Это безопасная сторона ошибки (выйдет шаблон вместо объяснения); насколько часто так происходит, измеряем в оценочных сценариях S5-07.

## Открытые пункты

- Провайдер, допустимые к отправке данные и лимит расходов — не выбраны (S5-01). Без этого реальные запросы не выполняются.
- Отправка комментариев наружу требует согласия заказчика: это тексты его сотрудников и клиентов. Если согласия не будет, комментарии выключаются (`ContextLimits(include_comments=False)`): `comments[]` пустой, в `comments_omitted` видно, сколько записей не отправлено, объяснение строится на фактах и показателях.
- Схема ответа модели и коды отклонения — S5-06.

# Шаблоны и демонстрационные данные

## Демонстрационный пакет (S6-04)

Четыре контрагента для показа продукта: обычный должник, серьёзный сигнал, ухудшение платежей и неполные данные. Ни одна оценка не подставлена — все четыре приоритета считают правила из `docs/scoring.md`.

Из корня репозитория, `PYTHONPATH` не нужен:

```bash
python examples/demo_package.py --what   # дата, период, ИНН и что про кого говорить
python examples/demo_package.py          # собрать .xlsx в examples/demo/
```

Файлы в репозиторий не кладутся: скрипт собирает одни и те же байты при каждом запуске (время сохранения из файлов вынуто), поэтому репетиция и защита показывают одинаковые числа, а пересобранный файл бот узнаёт как уже добавленный. Ход показа — `docs/demo-script.md`; определения пакета — `src/claims_assistant/infrastructure/demo/package.py`.

Пакет работает только с датой анализа `01.09.2026` (ввести руками, не «Сегодня») и периодом платежей `01.06.2026–01.09.2026`.

Чтобы бот отвечал по этому пакету, в `.env`: `DATA_PROVIDER=demo`, `DEMO_PACKAGE=true`, `AI_PROVIDER=off`. Без `DEMO_PACKAGE` источник даёт один сценарий на всех: сообщения о банкротстве у «Вектор-Лизинга» нет, и он становится средним. С `AI_PROVIDER=stub` в отчёте появится «ИИ: …», хотя модели на показе нет.

## Шаблоны файлов

Пустые шаблоны по [контрактам данных](../docs/data-contracts.md) бот присылает сам из диалога проверки: «Контрагенты», «Платежи», «История долга», «Взаимодействия».

Всё здесь синтетическое и помечено как демонстрационное. Настоящие данные должников в репозиторий не попадают и в реальные API из этих примеров ничего не уходит.
